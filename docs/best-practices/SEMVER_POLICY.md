# Политика версионирования (SemVer)

Библиотека следует [Semantic Versioning 2.0.0](https://semver.org/).

Формат: `MAJOR.MINOR.PATCH`

## Когда увеличивать PATCH

- Исправление бага, не меняющее публичный API.
- Обновление документации без изменения поведения.
- Внутренний рефакторинг без изменения экспортов.

**Пример причины:** `fix: корректная обработка circular reference в hashStructuredData`

## Когда увеличивать MINOR

- Добавление нового публичного экспорта (функции, типа, расширения).
- Добавление нового необязательного параметра в существующий API.
- Новое расширение (extension) в `src/extensions/`.

**Пример причины:** `feat: добавлен React route provider в extensions`

## Когда увеличивать MAJOR

- Удаление или переименование публичного экспорта.
- Изменение сигнатуры существующей публичной функции.
- Изменение формата `LogEntry` или `reqHash`.
- Изменение поведения, ломающее обратную совместимость.

**Пример причины:** `breaking: изменён формат reqHash, добавлено поле timestamp`

## Обязательно

- Каждый bump **должен** сопровождаться записью в `CHANGELOG.md`.
- В коммит-сообщении указывайте причину: `chore: bump 0.1.0 → 0.1.1 — fix hash truncation`.
- Версия **пакета** обновляется в `package.json`.
- Версия **схемы логов** каждого модуля обновляется в `src/<module>/config.ts` (`VERSION`, формат `MAJOR.MINOR`).
- Версия пакета и версии схем логов — **независимы**. Схема логов меняется только при изменении формата `LogEntry`/`RTLogEntry`.
