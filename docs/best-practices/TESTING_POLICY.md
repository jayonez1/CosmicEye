# Политика тестирования

## Главное правило

> **Тесты запрещено менять без явного запроса пользователя.**

Это означает:
- Нельзя изменять ассёрты, ожидаемые значения или тестовые сценарии.
- Нельзя удалять тесты.
- Нельзя менять логику `beforeEach`/`afterEach`, если это влияет на поведение тестов.

## Допустимые изменения без запроса

- **Перенос** тестовых файлов при реорганизации директорий.
- **Обновление import paths** из-за перемещения исходников.
- **Добавление новых тестов** для новой функциональности.

## Структура тестов

```
tests/
  rdr/                  # тесты ядра RDR
    hash.test.ts
    sampling.test.ts
    actions.test.ts
    rdr.test.ts
    lifecycle.test.ts
  extensions/           # тесты расширений (по директориям)
    <extension-name>/
      *.test.ts
```

## Команды запуска

| Команда | Область |
|---------|---------|
| `npm run test` | все тесты |
| `npm run test:rdr` | только RDR |
| `npm run test:extensions` | только extensions |
| `npm run test:watch` | все, watch-режим |
| `npm run test:watch:rdr` | RDR, watch-режим |
| `npm run test:watch:extensions` | extensions, watch-режим |

## Требования к новым тестам

- Использовать Vitest + jsdom.
- Fake timers: обязательно включать `performance` в `toFake` при тестировании временных интервалов.
- Моки модулей: использовать `vi.mock()` с правильными путями. После `vi.doMock()` обязательно вызывать `vi.doUnmock()` для изоляции.
- Каждый тестовый файл должен быть изолирован и не зависеть от порядка запуска.
