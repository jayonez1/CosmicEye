# Справочник по конфигурации

Все константы конфигурации определены в `src/config.ts`. Это константы времени компиляции — чтобы изменить их, измените исходный код и выполните пересборку.

## `VERSION`

| Значение | Описание |
|-------|-------------|
| `'0.1.0'` | Текущая версия библиотеки, включается в каждую запись лога |

## `IS_DEV`

| Значение | Описание |
|-------|-------------|
| `process.env.NODE_ENV !== 'production'` | `true` в разработке, `false` в production-сборках |

Управляет: обходом семплирования (всегда включён в dev), отправкой данных в расширение Chrome.

## `SAMPLING`

| Ключ | Значение | Описание |
|-----|-------|-------------|
| `RATE` | `0.05` | Доля пользователей production, попадающих в выборку (5%) |
| `STORAGE_KEY` | `'rum_user_id'` | Ключ `localStorage` для постоянного ID клиента |

Семплирование детерминированное: ID клиента хешируется FNV-1a и отображается в бакет `[0, 1)`. Если `bucket < RATE`, пользователь попадает в выборку.

## `TIMINGS`

| Ключ | Значение | Описание |
|-----|-------|-------------|
| `DUPLICATE_THRESHOLD_MS` | `1000` | Максимальное окно времени (мс) между запросами, чтобы считать их дубликатами |
| `CLEANUP_INTERVAL_MS` | `10000` | Интервал (мс) очистки просроченных записей из карты запросов |

## `FLUSH`

| Ключ | Значение | Описание |
|-----|-------|-------------|
| `INTERVAL_MS` | `15000` | Интервал периодического flush (мс) |
| `MAX_EVENTS` | `50` | Максимум записей лога до немедленного запуска flush |

## `HASH_LIMITS`

| Ключ | Значение | Описание |
|-----|-------|-------------|
| `MAX_DEPTH` | `20` | Максимальная глубина вложенности объекта при хешировании |
| `MAX_NODES` | `5000` | Максимальное общее число посещённых узлов (значений) при хешировании |
| `MAX_OBJECT_KEYS` | `300` | Максимальное число ключей объекта для хеширования |
| `MAX_ARRAY_ITEMS` | `1000` | Максимальное число элементов массива для хеширования |
| `MAX_STRING_CHARS` | `2048` | Максимальная длина строки для хеширования (дальше обрезается) |

Когда превышен любой лимит, хеш всё равно вычисляется, но `wasTruncated` устанавливается в `true`, что отражается в `truncationMask` у `reqHash`.

## `ACTIONS`

| Ключ | Значение | Описание |
|-----|-------|-------------|
| `BUFFER_MAX_SIZE` | `3` | Максимум событий пользовательских действий в буфере до сброса |
| `TRACKED_EVENTS` | `['click', 'keydown', 'touchstart']` | DOM-события, отслеживаемые для контекста `lastAction` |

## `CHROME_EXT`

| Ключ | Значение | Описание |
|-----|-------|-------------|
| `EVENT_NAME` | `'__RDR_LOG__'` | Имя `CustomEvent`, используемое для отправки данных лога в расширение Chrome DevTools (только dev) |
