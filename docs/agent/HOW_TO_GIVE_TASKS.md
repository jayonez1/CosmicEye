# Как давать задачи модели

Краткая инструкция для эффективного взаимодействия с AI-агентом по разработке CosmicEye.

## Формат задачи

```
=== КОНТЕКСТ ===
Что уже есть, какая версия, что было сделано ранее.

=== ЦЕЛЬ ===
Что нужно сделать. Одно-два предложения.

=== ACCEPTANCE CRITERIA ===
- [ ] Конкретный критерий 1
- [ ] Конкретный критерий 2
- [ ] Тесты проходят: npm run test
- [ ] Typecheck: npm run typecheck

=== ОГРАНИЧЕНИЯ ===
- Что НЕ делать.
- Какие модули НЕ трогать.

=== SEMVER ===
Тип bump: patch / minor / major
Причина: <одно предложение>
```

## Обязательные элементы

1. **Цель** — что конкретно должно измениться.
2. **AC** — как проверить, что задача выполнена.
3. **Ограничения** — что запрещено менять.
4. **SemVer** — какой тип bump и почему.

## Правила по умолчанию (не нужно повторять каждый раз)

- Тесты **запрещено** менять без явного указания `РАЗРЕШЕНО: изменить тесты`.
- После каждого изменения: обновить `CHANGELOG.md` и docs при необходимости.
- Публичный API не ломать без `РАЗРЕШЕНО: breaking change`.
- `src/index.ts` — только реэкспорты, без логики.

## Примеры

### Хорошо

```
ЦЕЛЬ: Добавить pluggable transport для flush (callback вместо console.log).
AC:
- [ ] Новый экспорт: setFlushTransport(fn)
- [ ] По умолчанию — console.log (обратная совместимость)
- [ ] Тесты на новый transport
ОГРАНИЧЕНИЯ: не менять существующие тесты.
SEMVER: minor — новый публичный API без breaking changes.
```

### Плохо

```
Сделай транспорт для логов.
```
