# Протокол обновления документации

## Команда

```
UPDATE_GUIDES
```

Пользователь пишет эту команду после завершения доработок, чтобы агент привёл документацию в актуальное состояние.

## Что делает агент при получении команды UPDATE_GUIDES

### 1. Анализ текущего состояния

- Прочитать `CHANGELOG.md` — определить, какие изменения были внесены.
- Прочитать `src/index.ts` — определить текущий публичный API.
- Прочитать `src/rdr/`, `src/rt/` и `src/extensions/` — определить состав модулей.
- Прочитать `tests/` — определить покрытие тестами.

### 2. Обновить документы (при необходимости)

| Документ | Когда обновлять |
|----------|----------------|
| `docs/checklists/UPDATE_CHECKLIST.md` | Если изменился процесс проверки (новые шаги, новые скрипты) |
| `docs/checklists/RELEASE_CHECKLIST.md` | Если изменился процесс релиза |
| `docs/best-practices/SEMVER_POLICY.md` | Если появились новые типы изменений |
| `docs/best-practices/TESTING_POLICY.md` | Если изменились правила тестирования или структура тестов |
| `docs/best-practices/DOCS_AND_CHANGELOG_POLICY.md` | Если изменилась структура docs |
| `docs/agent/HOW_TO_GIVE_TASKS.md` | Если появились новые правила или ограничения |
| `docs/rdr/CONFIG.md` | Если изменились конфигурационные константы RDR |
| `docs/rdr/EVENT_SCHEMA.md` | Если изменилась структура LogEntry (RDR) |
| `docs/rdr/INTEGRATION.md` | Если изменился процесс интеграции RDR |
| `docs/rt/CONFIG.md` | Если изменились конфигурационные константы RT |
| `docs/rt/EVENT_SCHEMA.md` | Если изменилась структура RTLogEntry |
| `docs/rt/INTEGRATION.md` | Если изменился процесс интеграции RT |
| `README.md` | Если изменились API, структура проекта или команды |

### 3. Отчёт

После обновления агент выводит:

```
UPDATE_GUIDES завершён.
Обновлены: <список файлов>
Без изменений: <список файлов, которые актуальны>
```

## Периодичность

- После каждого `minor` или `major` релиза — обязательно.
- После `patch` — по усмотрению, если изменились процессы.
- В любой момент по запросу пользователя.
