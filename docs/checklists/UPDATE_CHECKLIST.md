# Чек-лист после каждого обновления

Обязательные шаги после **любого** изменения в кодовой базе.

## 1. Проверки

```bash
npm run test          # все тесты проходят
npm run lint          # нет ошибок линтера
npm run typecheck     # проверка типов
npm run build         # сборка dist/
```

## 2. SemVer bump

- Определите тип изменения: `patch` / `minor` / `major` (см. `docs/best-practices/SEMVER_POLICY.md`).
- Обновите версию в **двух** местах:
  - `package.json` → поле `"version"`
  - `src/rdr/config.ts` → константа `VERSION`
- **Обязательно** укажите причину bump в коммите и CHANGELOG.

## 3. Документация

- [ ] Обновите `CHANGELOG.md` в формате [Keep a Changelog](https://keepachangelog.com/):
  - Секции: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`
- [ ] Обновите `README.md`, если изменился публичный API или структура.
- [ ] Обновите файлы в `docs/`, если изменились конфигурация, схема событий или процесс интеграции.

## 4. Тесты

- Тесты **запрещено** менять без явного запроса пользователя (см. `docs/best-practices/TESTING_POLICY.md`).
- Допускается: перенос файлов, обновление import paths при реорганизации.
- Новая функциональность **должна** сопровождаться новыми тестами.

## 5. Финальная проверка

```bash
npm run test          # повторный прогон после всех изменений
npm pack --dry-run    # убедиться, что в пакет попадают только нужные файлы
```
